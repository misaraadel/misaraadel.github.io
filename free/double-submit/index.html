سؤال إنترفيو: العميل اتخصم مرتين 💸 (Double Submit)

من ريل «داس مرتين… اتخصم مرتين» على إنستجرام:

👉 instagram.com/misarahamed.webdeveloper

المشكلة 💥

  • اليوزر داس على زرار «ادفع» مرتين بسرعة، أو النت كان بطيء فداس تاني.
  • كل ضغطة بتبعت Request للسيرفر، يعني ضغطتين = ٢ Requests = خصمين.
  • ولو عندك ١٠٠٠ أوردر في اليوم، هيبقى عندك عملاء كتير بيطلبوا فلوسهم ترجع، وناس مش هتشتري منك تاني.
  • اسم المشكلة دي في الإنترفيو: Double Submit.

الحل الأول: في الفرونت ✅

أول ما اليوزر يدوس، اقفل الزرار وحط لودينج، ولو حصل error رجّعه تاني.

const btn = document.querySelector('#pay');

btn.addEventListener('click', async () => {
  if (btn.disabled) return;          // لو الزرار مقفول، متعملش حاجة
  btn.disabled = true;               // اقفل الزرار
  btn.classList.add('loading');      // ⏳ لودينج
  try {
    await pay(order);
  } catch (err) {
    btn.disabled = false;            // فشل؟ رجّع الزرار علشان يجرب تاني
    btn.classList.remove('loading');
  }
});

في React ⚛️

function PayButton({ order }) {
  const [loading, setLoading] = useState(false);

  async function handlePay() {
    if (loading) return;
    setLoading(true);
    try {
      await pay(order);
    } finally {
      setLoading(false);
    }
  }

  return (
    <button onClick={handlePay} disabled={loading}>
      {loading ? 'جاري الدفع…' : 'ادفع ٥٠٠ ج.م'}
    </button>
  );
}

⚠️ الفرونت لوحده مش كفاية: لو النت قطع والمتصفح أو الكود عمل retry، أو حد بعت الـRequest من برّه الموقع، الزرار المقفول مش هيحميك.

الحل التاني: في الباك 🔑 (Idempotency Key)

  • Idempotent يعني: لو نفّذت نفس العملية مرة أو ١٠ مرات، النتيجة واحدة.
  • كل أوردر بياخد رقم مميز (Idempotency Key) بيتعمل مرة واحدة في الفرونت، ويتبعت مع كل محاولة دفع لنفس الأوردر.
  • السيرفر قبل ما يخصم يسأل: «الرقم ده اتدفع قبل كده؟» لو آه، يرجّع نفس النتيجة القديمة من غير ما يخصم تاني.

### الفرونت: ابعت المفتاح مع الـRequest

const key = crypto.randomUUID();   // مرة واحدة لكل أوردر، مش مع كل ضغطة

await fetch('/api/pay', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Idempotency-Key': key,
  },
  body: JSON.stringify({ orderId: order.id, amount: 500 }),
});

### الباك (Node.js + Express)

app.post('/api/pay', async (req, res) => {
  const key = req.get('Idempotency-Key');
  if (!key) return res.status(400).json({ error: 'Idempotency-Key مطلوب' });

  const old = await db.payments.findOne({ key });
  if (old) return res.json(old.result);       // اتدفع قبل كده؟ رجّع نفس النتيجة، من غير خصم

  const result = await chargeCard(req.body);  // أول مرة بس
  await db.payments.insert({ key, result });
  res.json(result);
});

💡 في المشاريع الحقيقية خلّي key عمود unique في الداتابيز، علشان لو جه Requestين في نفس اللحظة بالظبط، واحد بس اللي يتسجّل.

💡 بوابات الدفع الكبيرة زي Stripe بتدعم الـIdempotency-Key header جاهز.

🎯 ٣ أسئلة إنترفيو زيّه بإجاباتها

١) إيه الفرق بين Debounce وThrottle؟

  • Debounce: استنّى لحد ما اليوزر يبطّل، وبعدين نفّذ مرة واحدة (السيرش بار).
  • Throttle: نفّذ مرة واحدة كل فترة ثابتة مهما حصل (الـscroll أو الـresize).

٢) اليوزر كتب «iph» وبعدين «iphone»، ونتيجة «iph» وصلت متأخر وغطّت على الصح. تحلها إزاي؟ (Race Condition)

  • ألغي الـRequest القديم بـAbortController قبل ما تبعت الجديد:
let controller;
async function search(q) {
  controller?.abort();
  controller = new AbortController();
  const res = await fetch(`/api/search?q=${q}`, { signal: controller.signal });
  render(await res.json());
}

٣) أنهي HTTP methods اسمها Idempotent؟

  • GET وPUT وDELETE Idempotent: لو كررتها، النتيجة النهائية واحدة.
  • POST مش Idempotent: كل مرة بيعمل حاجة جديدة (أوردر جديد، أو خصم جديد)، علشان كده محتاج Idempotency Key.
